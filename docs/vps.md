# Развёртывание Printopus на VPS

Production-схема состоит только из долгоживущих сервисов на одном VPS: Caddy принимает HTTPS, Next.js работает постоянным Node.js-процессом, PostgreSQL хранит данные, а макеты заказов лежат в закрытом каталоге `/srv/printopus/uploads`.

## Требования

- Linux VPS с Docker Engine и Docker Compose;
- DNS-записи домена направлены на IP сервера;
- открыты входящие TCP-порты 80 и 443, а также UDP 443;
- наружу не опубликованы PostgreSQL и порт приложения 3000.

## Первый запуск

1. Скопировать `.env.production.example` в `.env.production` и заменить все секреты. Пароль PostgreSQL в `POSTGRES_PASSWORD` и внутри `DATABASE_URL` должен совпадать; специальные символы в URL нужно percent-encode.
2. Создать постоянный каталог макетов:

   ```sh
   sudo install -d -o 1001 -g 1001 -m 0750 /srv/printopus/uploads
   sudo install -d -o root -g root -m 0700 /srv/printopus/backups
   ```

3. Собрать и запустить сервисы:

   ```sh
   docker compose --env-file .env.production -f compose.production.yaml up -d --build
   ```

Миграции PostgreSQL выполняются отдельным одноразовым контейнером до запуска приложения. Caddy автоматически получает и обновляет TLS-сертификат.

## Обновление

Перед обновлением создать резервную копию, получить новую версию проекта и повторить команду `up -d --build`. Постоянные данные не находятся внутри контейнера и переживают пересборку.

## Резервные копии

Команда сохраняет согласованный дамп PostgreSQL и архив каталога макетов в отдельную папку с UTC-временем:

```sh
sudo ./scripts/backup-vps.sh
```

Копии из `/srv/printopus/backups` нужно регулярно переносить на другой сервер или зашифрованный внешний диск. Резервная копия, оставленная только на том же VPS, не защищает от потери самого сервера. Периодически следует проверять восстановление дампа и архива на тестовой машине.

Файл `.env.production` не входит в резервную копию: секреты следует отдельно хранить в менеджере паролей или другом защищённом хранилище.

## Файлы заказов

- Допускаются только JPEG, PNG и WebP, максимум 10 МБ на файл, 5 файлов и 25 МБ суммарно на заказ.
- Расширение и MIME не считаются доказательством: сервер проверяет сигнатуру, полностью декодирует изображение и отклоняет видео, SVG, анимацию и повреждённые файлы.
- Изображение перекодируется без исходных метаданных и записывается под случайным именем.
- Каталог загрузок не публикуется Caddy и недоступен через `public/`; скачать макет можно только из авторизованной админки.
- Приложение прекращает принимать файлы, если после записи на диске останется меньше 1 ГБ свободного места; резерв меняется через `UPLOAD_MIN_FREE_BYTES`.

## Проверка состояния

`GET /api/health` возвращает `200`, только когда PostgreSQL доступен, а каталог загрузок существует и доступен на чтение и запись. Docker использует этот маршрут для проверки работоспособности приложения.
